## Technical boundaries
- Existing branch: feat/sample-vacancies-filters. Preserve unrelated untracked business/discovery documentation. No commits, push, services, migrations or backend writes.
- Choose one compatible stable Tiptap release using registry metadata and inspected installed source; pin direct packages exactly and record resolved versions. Do not assume upstream main equals the installed version. No broad dependency upgrades.
- Existing frontend requires Node >=22 <23 and pnpm 10.34.5. Report unavailable runtime rather than weakening engine checks. Package-manager generated cache/install artifacts are allowed inside this checkout; do not change global configuration.
- Add a small test-only schema module under frontend/src/features/jobs/tiptap-contract-proof/ (relocated outside the production form-module boundary); do not connect it to the UI. Explicit minimal extensions, not unfiltered StarterKit.
- Verify empty doc is a paragraph-containing document; text nodes nonempty. Probe native link attrs including target/rel/class/title, ordered-list start, hardBreak marks and actual mark order. No speculative normalization or silent stripping of unknown data.
- Size mark fontSizePreset carries a constrained size enum. Test small/normal/large actions, mixed marks, selection changes, typing, undo/redo and serialization/restoration. Report exact choice for normal and verify it rather than silently changing the shared contract.
- Separate supported external HTTP(S) URL policy from old token-parser punctuation restrictions. Test unsafe URI rejection; JSON is not inherently trusted. A spike is not a complete Go security validator.
- Emit a bounded JSON fixture corpus of actual editor output and expected plain text for Go. Include empty paragraphs, Unicode, lists including start !=1/nesting, hard breaks and combined marks. Plain extraction proposal: concatenate inline text, hardBreak newline, join block/list/item children with newline, no trimming or markers. Explain unsupported cases.
- Applicable tests: observe meaningful RED for custom size/security behavior, then GREEN. Native serialization discovery has no meaningful prior RED; record actual execution separately. Run focused tests, existing suite and typecheck; report every failure or unavailable check. No Next build/browser-E2E claim from jsdom tests.
- Keep authored proof small. If scope grows beyond a bounded contract experiment, stop with a concrete split proposal.
