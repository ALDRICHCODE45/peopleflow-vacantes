# Audited internal edits of organization candidates (UI)

Frontend side of SRCH-4 (closes the «org pool + audited edits» unit). Branch `feat/org-candidate-edits-ui` from main
659b639. Backend counterpart: session 01a16189-7c44. Merge is done by the backend in its worktree; the user pushes.

## Specs

- **S1** (L2). Any candidate of the organization can be corrected, manual or organic: «cualquier dato del postulante debe poder modificarse, pero obviamente eso no va a modificar el perfil del candidato». Manual records are edited directly; organic candidates get a company-only correction layer over what they shared, the original stays visible and the candidate's own profile never changes.
- **S2** (L2). The same fields for both kinds: «apoco los datos del candidato manual son distintos que los de el candidato organico?? deberian ser los mismos no?» — contact (name, email, phone E.164), location, professional title, current company, seniority, years, education, languages, skills, links, with the manual-intake validation.
- **S3** (L2). «Cualquier reclutador (recomendado)»: every recruiter of the company can edit.
- **S4** (L2). «Contacto sin valores (recomendado)»: a «Historial de cambios» in the candidate sheet shows who, when and which field; contact fields without values («Teléfono modificado»), other fields previous → new.
- **S6** (L4). «Sí, en esta unidad (recomendado)»: the vacancy board (candidate sheet, board profile and CV download) also shows the corrections — corrected CV as current with access to the original — as the last cut.
- **S5** (L2, L3). A corrected CV can be attached internally (wrong or outdated CV), without deleting the candidate's original; the current CV is marked and the original stays accessible.
