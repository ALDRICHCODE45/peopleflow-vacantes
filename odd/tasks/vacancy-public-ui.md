# Public vacancies P2a (frontend)
Show published vacancies on the public site next to legacy catalog jobs through the new `/v2/jobs` contract, and handle the new «published content cannot become incomplete» rule on the employer save screens.
Branch feat/vacancy-public-ui stacked on feat/vacancy-publication-ui (122df2f); nothing here is merged to main until the user tests P1 and P2a in the browser (docs/pending-user-review.md). Frontend only, in parallel with the backend session (01a1420b-ba06-7632) on feat/vacancy-public (stacked on feat/vacancy-publication). ## Specs
- S1. User: «…que sigan implementando features en medida de lo posible por favor, y vayan acumulando las cosas que yo tengo que revisar, cuando llegue a mi casa, lo reviso todo y hago los comentarios/mejoras necesarias, pero no quiero atascar el trabajo. si puedo responderles y contestar sus dudas pero no puedo ver nada en el navegador.» Standing rules: docs/frontend-ui-design-rules.md (incl. §12 ActionBar, §13 patterns) and shadcn first; audit against §9 before reporting; add new patterns to the rules; every visual decision is listed in docs/pending-user-review.md.
- S2. Product decisions relayed by the backend: «P2 se parte en P2a (listado/detalle) y P2b (CVs + postular).»; «Una vacante publicada no se puede guardar con un requisito faltante.»; «Filtros de P2a: texto, ubicación, modalidad, jornada, contrato y área. Salario e idioma van en otro corte.»
- S3. `GET /v2/jobs` (anonymous): params `q`, `location`, `work_mode` (onsite|remote|hybrid), `work_schedule` (full_time|part_time), `contract_type` (project|indefinite|professional_services|temporary|internship), `professional_area` (16 catalog codes), `limit` 1-50 default 20, `cursor`; each at most once, unknown keys and invalid values → 400 invalid_request. Envelope `{items, next_cursor}`. Item keys always present: id (uuid), source (legacy|vacancy), title, company {id, name}, location, work_mode, work_schedule, contract_type, professional_area, seniority (intern|junior|mid|senior|lead; null allowed for vacancy, never for legacy), legacy_employment_type, compensation, legacy_salary, published_at (RFC3339, never null). Legacy: work_schedule/contract_type/professional_area null. Vacancy: legacy_employment_type/legacy_salary null. compensation = draft v2 compensation without public_visible, key `pay_period` (not `period`), only when public and complete, else null. legacy_salary = {min, max, currency} with decimal-string nullable min/max, null when both null. Schedule/contract/area filters exclude legacy rows.
- S4. `GET /v2/jobs/{id}` → list shape + `description` (rich document for vacancy, null for legacy), `description_plain`, `requirements {required, preferred}` (nullable strings; both null for legacy), `benefits {predefined: [codes], custom: [strings]}` (empty arrays for legacy). 404 not_found for unknown, unpublished or inactive-company ids. No ETag, public caching like the legacy routes; envelope {error, code}.
- S5. UI: /vacantes and /vacantes/{id} read /v2/jobs; filters text, location, modality, schedule, contract, area (salary and language filters removed until their cut); a visible note when a schedule/contract/area filter is active that catalog-only (legacy) offers are excluded; vacancy detail renders the rich description (reuse the draft rich renderer), requirements and benefits with catalog labels; the apply action stays for legacy rows and is hidden for source=vacancy until P2b (no «próximamente» copy, rules §6/§13.4); only VAC-4 content.
- S6. Employer screens of a published vacancy (draft editor save, Entrega, Solicitud): a 422 publication_incomplete on save is shown as «La vacante está publicada: no puedes dejarla sin …» listing the missing items (labels from publication-model.ts), edits kept, no retry.
