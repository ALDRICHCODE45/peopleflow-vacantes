# Employer draft list and reopen
Let the recruiter find saved private drafts, reopen one, edit it and save it again (continues odd/tasks/private-vacancy-drafts.md T8).
Branch feat/draft-list-and-reopen from main 40c91ea. Frontend only; the backend session (01a14144-6e8a) owns GET /v2/me/company/job-drafts on its branch feat/draft-list.

## Specs
- S1. User request relayed verbatim by the backend session: «Si hermano, estoy de acuerdo, por favor. coordinate con el frontend para poder hacer eso, mientras tu trabajas con el backend, el frontend hace la ui y conecciones necesarias». Goal stated by the backend: «que el reclutador encuentre sus borradores guardados y pueda reabrirlos, editarlos y guardarlos». The user also said: «solamente tocas el frontend, no el backend, el backend tiene su propio agente encargado, por favor.»
- S2. List contract (backend proposal, accepted by frontend): `GET /v2/me/company/job-drafts?limit=&cursor=`, Bearer, Cache-Control no-store. 200 `{"items":[{"id":uuid,"title":string|null,"work_mode":"onsite"|"remote"|"hybrid"|null,"work_schedule":"full_time"|"part_time"|null,"requester":null|{"kind":"internal_area"|"client","id":uuid|null,"name":string|null},"principal_recruiter":{"id":uuid,"name":string|null},"version":string,"created_at":RFC3339,"updated_at":RFC3339}],"next_cursor":null|string}`. Order updated_at DESC, id DESC; limit default 20, range 1..50; next_cursor opaque, sent back as-is (URL-encoded). Owner sees every v2 draft of the company; a recruiter only those where they are the principal recruiter (so for a recruiter it is always themself); principal_recruiter.name is null only for a soft-deleted user; title null is valid; requester {kind, id:null, name:null} is valid (kind without catalog entry) and when id is not null name is always a string; v1 drafts never appear; no search or filters. Unknown query parameters are ignored; a repeated `limit` or `cursor` is 400 invalid_request. Errors `{error,code}`: 400 invalid_request, 401 unauthenticated, 403 forbidden, 403 company_inactive, 409 company_not_active, 500 internal_error. A draft saved while paginating moves to the top and may be missing from later pages; refreshing without a cursor shows it again.
- S3. Reopen: the list row is for display only; editing loads the draft with `GET /v2/me/company/job-drafts/{id}` and saves with `PATCH` + `If-Match` from that GET's ETag, never from the list `version`. Hydration must not lose or alter any stored field: reopening and saving without edits sends back the same field values.
- S4. Same safety rules as the existing save path: server-only client, Bearer only, redirect "error", strict decoders, no automatic mutation retries, no false success, results through notifyActionResult + ActionStatusSlot (no layout shift).
- S5. User: «Hermano, recuerda las reglas de ui que tenemos escritas en nuestro system design propio, y tambien recuerda el uso primordial de shadcn.» All UI follows docs/frontend-ui-design-rules.md and is built primarily from shadcn components in frontend/src/components/ui.
- S6. User (browser test, 2026-10-15): «no tengo idea poruqe creaste una ruta aparte para ver los borradores mediante un boton de "Borradores" en la lista de las vacantes que ES en donde deben aparecer todas las vacantes, se deben mostrar de la misma forma que todas las vacantes, incluso las que son borradores, cuando presionen el pipeline, lo llevara a la ruta del pipeline pero habra un mensaje de que no hay ningun pipeline porque la vacante esta en borrador, es decir, ponle mas carino por favor, mas esfuerzo. recuerda seguir tu reglas de diseno y priorizar shadcn, gracias.» Saved drafts appear in the /empresa/vacantes table as rows with the same composition as every vacancy and a «Borrador» state; there is no separate drafts list route and no «Borradores» button. «Ver pipeline» on a draft opens /empresa/vacantes/{id}/pipeline, which explains that the vacancy has no pipeline because it is a draft. Supersedes the T4 list page (S2 contract stays).
