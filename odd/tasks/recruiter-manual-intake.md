- **S9** Agreed cut-B contract (L5–L6). Model: new `company_candidates` (company_id, full_name, email?, phone?, education_level, residence country/state/municipality/postal_code?, optional profile fields, created_by, created_at) and `company_candidate_cvs` (same private storage and rules as candidate CVs: PDF/DOCX, 5 MiB, `cvs.Inspect`); participation gains `company_candidate_id`, exactly one of `candidate_id`/`company_candidate_id`; `source` organic|manual; additive migrations. Never in global search (SRCH-7). Base `/v2/me/company/job-drafts/{id}/pipeline/candidates/manual`:
  1. `POST …/duplicates-check` JSON `{"email":string|null,"phone":string|null}` (at least one) → 200 `{"matches":[{"kind":"manual"|"organic","id","full_name","email_masked"|null,"phone_masked"|null,"last_vacancy":{"id","title"}|null,"last_added_at","in_this_process":bool}]}`. Scope only the company: its manual records plus organic users with any participation in its processes (including discarded/finished). Match by normalized email (trim+lowercase) or exact E.164 phone. Masks «a***@dominio.com», «+52 •••• ••12 34» (last 4).
  2. `POST …/manual` multipart, Idempotency-Key UUID required (apply/lifecycle replay scheme): part `data` JSON + part `cv` file (required). `data` = `{"stage_id","existing":{"kind","id"}|null,"confirmed_distinct":bool,"candidate":{…}|null}`. With existing → candidate null (reuse; kind organic creates a source=manual participation on that user, hidden from their candidate panel). Without existing → candidate required; server rechecks duplicates; matches and not confirmed_distinct → 409 `possible_duplicates` data `{"matches":[…]}`, no writes. Already in this process → 409 `candidate_already_in_process`. Success 201 with the board item (same shape) and its ETag.
  candidate: full_name (2–120, identity rules), education_level high_school|bachelor|master|phd, email|null, phone|null (≥1; E.164: "+52"+10 digits for MX; other countries + 6–14 digits, total ≤15), residence `{"country","state","municipality","postal_code"|null}` (G3 validator: MX requires state+municipality, optional coherent 5-digit CP; outside MX no subdivisions). Optional: professional_title, current_company, field_of_study, experience_years (integer 0–60), summary, skills [], languages [{"language","level":A1..C2}], linkedin_url, portfolio_url. No birth date, no salary.
  stage_id: any current pipeline stage except Placement and the exit (Descartados). Process must have been published and be active (finished → 409 process_finished; never published → 409 vacancy_not_published). Entering at/after the delivery cutoff records delivery like a move. No notification.
  Field errors → 422 `validation_error` with `fields:[{"field":"candidate.phone","code":"invalid"|"required"}]`; malformed shape/multipart → 400 invalid_request; invalid CV → the same codes as `POST /v2/me/cvs`.
  Reads: board item/detail `source` organic|manual, new always-present `added_by` {"id","name"}|null (null for organic); `applied_at` is the intake date; `candidate.kind` organic|manual. Manual CV downloads through the existing board CV route. History intake entry with the recruiter as actor. Candidate panel excludes manual participations. Audit `VacancyCandidateAddedManually`. Eligible stages come from the board (frontend).
