# Pipeline discard and recovery cut 5 (frontend)
Discard a candidate with a reason (recruiter or candidate decision), optional internal comment and optional message for the candidate, and recover a discarded candidate to its previous stage, on the real board and candidate sheet; the candidate sees «Finalizada» plus the message.

- S2. - S3. Catalog (§13.1): recruiter — requirements_not_met «No cumple requisitos», profile_mismatch «Perfil no adecuado», salary_expectation «Expectativa salarial», other_candidate_selected «Seleccionamos a otra persona», other «Otro»; candidate — accepted_other_offer «Aceptó otra oferta», no_longer_interested «Ya no le interesa», unresponsive «Sin respuesta del candidato», other «Otro». Group titles «Decisión de la empresa» (recruiter) / «Decisión del candidato» (candidate). `other` requires a comment.
- S4. Text rules (§13.6.1): comment 1–1,000 and candidate_message 1–500 Unicode code points after trimming leading/trailing Unicode White_Space; interior kept; control characters other than \n and \t rejected; empty optional fields are omitted (never send ""). Plain text only.
- S5. POST `…/participations/{pid}/discard`, If-Match = item etag unchanged, body exactly {reason:{group,key}, comment?, candidate_message?, confirm_placement_exit?}; discarding from Placement requires confirm_placement_exit: true (409 placement_exit_confirmation_required otherwise). POST `…/recover`, If-Match, body {confirm_placement_reentry?} ({} valid); recovering into Placement requires confirm_placement_reentry: true (409 placement_reentry_confirmation_required). Both → 200 item + coverage + new ETag like a move. 409 already_discarded / not_discarded / 412 / 404 / uncertain → reload the board once, never retry; 400 validation_error has no details (generic error, keep the user's input).
- S6. Board items gain `discard`: null | {reason:{group,key}, discarded_at, previous_stage_id}; discarded items have stage_id = exit.id, count in exit.count, moved_at = discarded_at; previous_stage_id is always a current stage. Detail gains `discard`, `comment`, `candidate_message`, always present, null unless currently discarded. History is a discriminated union: intake/move unchanged; discard {kind, from_stage_id (previous), to_stage_id (exit), hire false, departure, reason, comment|null, candidate_message|null, actor, at}; recovery {kind, from_stage_id (exit), to_stage_id (previous), hire, departure false, actor, at}. Moves never target or leave Descartados.
- S7. UI (§13.4): «Descartar» action on the card and in the candidate sheet with the reason (grouped), comment, optional candidate message and the Placement exit confirmation; the Descartados column shows each card's reason; «Recuperar» with confirmation (naming the previous stage) plus the Placement re-entry confirmation; the sheet history shows discard (reason, comment, message) and recovery entries.
- S8. Candidate list: status submitted | in_process | closed (strict) with `message` always present (null unless closed); /candidato/postulaciones shows «Enviada» / «En proceso» / «Finalizada» and the message as plain text when closed.
