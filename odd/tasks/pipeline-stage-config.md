# Pipeline stage configuration (cut 1)
Let the recruiter configure the columns of a draft vacancy's pipeline: rename every stage, reorder between Nuevos and Placement, add up to 3 custom columns and remove them.

- S4. Contract GET `/v2/me/company/job-drafts/{draftId}/pipeline` → 200 `{"version": decimal string ("0" = defaults never saved), "stages":[{"id":uuid,"kind":"new"|"screening"|"screening_ok"|"in_process"|"placement"|"custom","name":string}], "exit":{"id":uuid,"kind":"discarded","name":string}, "limits":{"maxCustomStages":3,"nameMaxLength":40}}` + strong opaque pipeline `ETag` (never built by the client, never equal to a draft tag). Pure GET; built-in ids deterministic. Unknown kind → invalid response.
- S5. Contract PUT same path, `If-Match` required, body exactly `{"stages":[{"id"?,"name"}],"exit":{"id","name"}}` (no kind; id-less entry = new custom; removed custom omitted; unknown keys rejected) → 200 same body shape in request order with server ids for new custom stages + new ETag. No-op PUT returns the same version. Uncertain PUT is not retried: reconcile with GET. No Idempotency-Key.
- S6. Invariants (validated client-side before sending): exactly one of each built-in kind, built-ins never removed; `new` first and `placement` last in the progression, everything between freely reorderable; `discarded` only in exit; at most `limits.maxCustomStages` custom; names: NFC → trim + collapse Unicode White_Space (incl. NBSP) to one ASCII space, non-whitespace control characters rejected, format characters kept, 1–`limits.nameMaxLength` code points; names unique across progression and exit on the full-Unicode casefold of the normalized name, accents preserved (`Área` = `ÁREA`, `Area` ≠ `Área`). Descartados is renameable.
- S7. Errors `{error, code}` without details: 400 invalid_request, 400 validation_error (shown as a generic failure keeping the edited state), 401, 403 forbidden / company_inactive, 404 not_found (missing, foreign or non-principal draft), 409 company_not_active, 412 version_conflict (no data), 413 payload_too_large, 428 precondition_required, 500 internal_error. Every response no-store.
- S8. PIPE-10: renaming a stage with a critical action (`in_process`, `placement`, `discarded`) requires a dialog explaining that the action remains unchanged. Colors derive from kind client-side; custom stages neutral. Reorder with accessible up/down buttons, Nuevos and Placement fixed.
- S9. Same safety rules as the draft save path: server-only client, Bearer only, redirect "error", strict decoders, no automatic mutation retries, no false success, results through notifyActionResult + ActionStatusSlot (no layout shift).
