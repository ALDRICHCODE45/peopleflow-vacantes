# Authored interview bank v1

Backend-owned content, selected without AI. Every row defines one unique question id; references may repeat ids, definitions may not. Selector `low`, `medium` or `high` means the corresponding band id; `adjacent`, `distant` or `quality` means the corresponding focus type. All seven competencies have two questions for each selector (84 questions). A focus question uses both observed and desired band in its stored selection reason, never a generated question rewrite.

Candidate-facing introduction: «Te voy a pedir ejemplos de tu experiencia de trabajo. Puedes usar ejemplos de proyectos o actividades de estudio si aún no has trabajado. No necesitas compartir nombres ni información privada.»

For **every** selected question, append this fixed STAR follow-up: «¿Cuál era la situación y qué necesitabas lograr? ¿Qué hiciste tú, qué resultado hubo y qué aprendiste?» This is part of the rendered and stored question text, not an optional interviewer improvisation. It applies equally to quality questions: ask about the actual assessment experience and one work example, never private causes. Recruiter instruction: «Busca ejemplos concretos y acciones propias. Si algo no queda claro, pide un detalle; no asumas una intención.»

“What a good answer shows” is an evidence checklist, not a rating key or a favored personality band. A specific unsuccessful example with reflection can be useful evidence. Do not score eloquence, accent, employer prestige or disclosure of private circumstances.

## Deterministic guide selection

Selection inputs are the immutable result bands, fit entries, focus instances and confirmed profile snapshot, plus content/scoring versions. No live vacancy edits, candidate attributes, answer speed ordering, randomization or AI. The backend selects at completion and stores the selected questions with the initial comparison. A later explicit comparison uses the same pinned content/scoring pair and immutable bands, but the newly confirmed profile; it stores a separate guide without overwriting the first. The frontend renders that stored guide; it does not select or receive the full bank.

1. Build one ordinary block per relevant competency (Clave or Importante). With no confirmed profile or no relevant entries, build one per catalog competency with null importance/fit and use the observed band; this is an exploratory guide, not job comparison. A competency's selector is its gap focus if present (`distant` or `adjacent`), otherwise its observed band. Each block contains that selector's questions 1 then 2.
2. Sort ordinary blocks by job importance (Clave, Importante, null), then focus priority (distant, adjacent, none), then competency id lexicographically ascending. This preserves job importance as primary priority; fit is already determined by importance and gap. No selection uses a numeric total match score.
3. If `focus.quality` exists, reserve one of four block slots for its routed competency (routing in the bands document). Take the first three ordinary blocks, then append the quality block (questions 1 and 2). Otherwise take the first four ordinary blocks. Thus the guide has 2–8 questions in pairs, with at most 8; fewer relevant competencies means fewer ordinary blocks, not padding with irrelevant competencies. A competency can have an ordinary block and a quality block, but question ids differ. No duplicate question ids.
4. Render in that order. Persist the entire resolved Spanish question plus fixed STAR follow-up, good-answer checklist, question id, competency id, observed band, selector, fit (nullable), desired band (nullable), importance (nullable), originating focus id/type if any and triggered signal ids for quality. Also store ordered ids, profile version (nullable), scoring_version and content_version. Quality routing must be labeled «Contexto de respuesta», not presented as a competency gap.
5. For band blocks show the competency name and observed band as origin. For gap blocks additionally show desired band, importance, fit and focus type. For quality blocks show observed band for context plus tier and triggering signals; never imply that this band caused the quality signal. Lookup failure or missing input is an incomplete guide, not permission to invent a question or silently switch versions.

Examples: with seven relevant competencies and no quality focus, select four ordinary blocks = eight questions; with one relevant competency and quality focus, select its ordinary block then the routed quality block = four questions. With no confirmed profile and no signals, choose comp.colaboracion, comp.compromisos, comp.coordinacion and comp.deliberacion and their observed-band questions (the first four ids alphabetically). With only comp.presion relevant, observed band.low and desired band.high at importance.clave, choose q.presion.distant.1 then q.presion.distant.2; if quality is present, append q.presion.quality.1 then q.presion.quality.2. Every question includes the fixed STAR follow-up. Repeat selection with identical stored inputs and versions yields identical ordered ids and text. Changing an interviewer note never regenerates a guide.
