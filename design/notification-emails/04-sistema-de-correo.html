Correos transaccionales de PeopleFlow · U1 · S1

04 · Sistema de correo (común a las tres direcciones)

Reglas compartidas: anatomía, cómo se asigna tipo, tono y urgencia a las 17 plantillas, modo oscuro, compatibilidad, privacidad, cómo llevarlo a Go html/template y lo que falta decidir. El interruptor de tema solo afecta a esta página.

Anatomía común

  1. Preheader oculto = línea de cuerpo (texto plano).
  2. Marca: «peopleflow» como texto vivo; nunca depende de una imagen.
  3. Contexto: nombre de la empresa (en correos de empresa, solo 01 lo pinta arriba; en candidato, todas lo muestran como identidad).
  4. Identificador de tipo: etiqueta (01), mosaico + franja (02) o sello + barra (03).
  5. Urgencia («Vencida», «Vence pronto») y «Obligatorio»: siempre con palabra, nunca solo color.
  6. Título = «Heading» de la plantilla, en <h1>.
  7. Línea de cuerpo = «Body line», con las variables en 600.
  8. Un solo botón violeta = «Button».
  9. Pie F1 (opcional, con baja) o F2 (obligatorio, sin baja).
  10. Línea legal con la dirección postal de PeopleFlow.

Tres ejes, no diecisiete diseños

Tipo decide el pie y la marca «Obligatorio» (operativo, obligatorio, candidato). Tono viene de la familia del aviso, igual que en la campana (postulaciones violeta, pruebas completadas verde, asignaciones azul, entregas ámbar/rojo). Urgencia solo existe en entregas: ámbar «Vence pronto», rojo «Vencida».

El botón siempre es violeta: el color de estado marca qué pasó, no la acción.

Modo oscuro

  • Estilos en línea = claro (lo que ve un cliente que ignora <style>).
  • <meta name="color-scheme" content="light dark"> + supported-color-schemes.
  • Clases .pf-* con los valores oscuros del sistema en @media (prefers-color-scheme: dark) (Apple Mail, iOS, Outlook macOS, Thunderbird).
  • Las mismas reglas con [data-ogsc] / [data-ogsb] para Outlook.com.
  • Gmail app y Outlook Windows invierten por su cuenta: colores sin blanco puro en texto sobre violeta, sin imágenes con fondo, la marca es texto, así que la inversión no rompe nada.

Compatibilidad

  • Maquetación en tablas, role="presentation", ancho máximo 600 con tabla fantasma <!--[if mso]>.
  • Botón: v:roundrect en Outlook escritorio; en el resto, enlace con relleno sobre celda con bgcolor.
  • Outlook escritorio no pinta radios ni border-radius:50%: tarjetas y sellos quedan cuadrados, el resto se conserva.
  • Sin CSS ni JS externos, sin fuentes remotas; Inter solo si está instalada.
  • Teléfono: una regla @media (max-width:620px) reduce márgenes, baja el título y pone el botón a todo el ancho; Gmail con cuentas no Google la ignora y ve la versión de escritorio, que ya cabe a 375 por el ancho fluido.

Privacidad y datos

  • Ningún correo lleva nombre de candidato ni de integrante (L18); el mensaje de T16 no se incluye.
  • Datos nuevos que el backend debe pasar: company_name en todos (hoy solo T11, T15–T17), company_initials para candidato y el conteo como símbolo en agrupados (02 y 03).
  • Remitente propuesto: «PeopleFlow <avisos@…>» (dominio por definir).

Go html/template · datos

// Un solo layout por dirección; las 17 plantillas solo llenan EmailView.
type EmailView struct {
    Subject, Preheader      string // Preheader = línea de cuerpo en texto plano
    Heading                 string
    Body                    template.HTML // línea de cuerpo con <strong> en las variables
    ButtonLabel, ButtonURL  string
    Kind                    string // "operational" | "mandatory" | "candidate"
    ToneName                string // "primary" | "info" | "success" | "review" | "danger" (sufijo de las clases .pf-*)
    Tone                    Tone   // tones[ToneName]
    Eyebrow                 string // "Postulaciones", "Entrega", ... o CompanyName (candidato)
    Glyph                   string // "!", "→", "+", "✓", "…", el conteo o CompanyInitials
    Urgency                 string // "" | "Vencida" | "Vence pronto"
    CompanyName             string // contexto en correos de empresa; identidad en candidato
    CompanyInitials         string
    Mandatory               bool   // true → F2; false → F1
    PreferencesURL          string
    UnsubscribeURL          string // vacío si Mandatory
    LegalAddress            string
}

type Tone struct{ Text, Tint, Wash, Border, Fill, OnFill string } // hex, claro

Por qué así en Go

  • Un layout por dirección + 17 definiciones de EmailView; ninguna plantilla repite HTML.
  • html/template escapa los atributos style: pasar solo hex de la tabla tones (pasa el filtro CSS); nunca concatenar CSS que venga del usuario (saldría ZgotmplZ).
  • Body se arma en Go con las variables escapadas dentro de <strong> y luego se marca template.HTML.
  • El bloque <style> es fijo y va en un {{define "styles"}}.
  • Muestras HTML listas para Mailpit: design/notification-emails/samples/.

Por aprobar antes de implementar

  • La dirección (01, 02 o 03).
  • Microcopia nueva: antetítulos de familia, «Vencida», «Vence pronto», «Obligatorio».
  • Dirección postal de PeopleFlow para la línea legal y dominio del remitente.
  • Si se quiere logo en imagen: exportar el wordmark a PNG @2x (256 × 64) claro; la versión oscura no se puede garantizar, por eso el texto vivo es la opción por defecto.
  • Opcional (no está en la copia acordada): enlace de respaldo bajo el botón («¿No funciona el botón? Copia este enlace»).
