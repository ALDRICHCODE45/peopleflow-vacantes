### 4.1 RED (compile) — Author `applications.sql` (6 queries) and regenerate (D1/D3/D5/D10)
- [x] 4.1 RED — Author the six queries exactly per design §3; run sqlc; confirm the generated seam. <!-- sdd-owner: implementation -->

`backend/db/queries/applications.sql` (NEW): the six queries from design §3/§5.6, verbatim shapes:
- `CreateApplication :one` — `INSERT ... SELECT sqlc.arg('id'/'job_id'/'candidate_id')::uuid, sqlc.narg('source')::text, sqlc.narg('cover_letter')::text WHERE EXISTS (SELECT 1 FROM jobs j JOIN companies c ON c.id = j.company_id WHERE j.id = sqlc.arg('job_id')::uuid AND j.status='published' AND j.deleted_at IS NULL AND c.status='active') RETURNING id, job_id, candidate_id, status, source, cover_letter, created_at, updated_at` — `status` NOT in the INSERT (DB `DEFAULT 'submitted'` wins); `cv_s3_key`/`anonymized_at` in NEITHER the INSERT nor the RETURNING (D1, D11). Doc comment pins the atomic-gate rationale.
- `GetApplicationByID :one` — scope `(id, job_id, j.company_id)` + `JOIN users u` (full_name) + `LEFT JOIN candidate_profiles cp` (professional_title, years_of_experience); PII-minimized column list only (D12).
- `ListApplicationsByJob :many` — same columns as GetApplicationByID, `WHERE a.job_id AND j.company_id`, `ORDER BY a.created_at DESC, a.id DESC LIMIT 100`.
- `ListMyApplications :many` — application columns + `j.title AS job_title`, `c.id AS company_id`, `c.name AS company_name` via `JOIN jobs` + `JOIN companies`; `WHERE a.candidate_id`, `ORDER BY a.created_at DESC, a.id DESC LIMIT 100`; NO `jobs.deleted_at` filter (history preserved).
